# Tsubaki (つばき), a text editor for PC-98 / FreeDOS(98)

**Tsubaki（つばき）**は PC-98 / FreeDOS(98) 向けのテキストエディタです。
ソースは `TSUBAKI.C`、実行ファイルは `TSUBAKI.EXE` です。**開発中**で、
現時点（第0マイルストーン、v0）ではファイルを開く・新規作成・保存・
名前を変えて保存・終了（未保存確認つき）、カーソル移動、文字入力
（半角・全角）、改行・BS・DEL・行削除、挿入／上書きの切替、横スクロール
ができます。設計の詳細は `docs/tsubaki-spec-01.md` を参照してください。

同じプロジェクトのファイラ「すみれ」（`guest/sumire/`）とは兄弟にあたり、
DOS/BIOS 呼び出し・テキストVRAM直書き層・ダイアログ機構・言語切替機構の
土台部分を共有しています（下記「独立実装であることの宣言」参照）。

## 表示言語

画面表示は日本語・英語の両方に対応しています。コマンドライン引数で
切り替えます。

- `TSUBAKI /J` … 日本語（既定。引数を省略した場合も日本語になります）
- `TSUBAKI /E` … 英語
- `TSUBAKI <ファイル名>` … 指定したファイルを開いて起動します（存在しない
  場合は、そのファイル名を宛先とした新規文書として起動します）
- 引数を何も指定しない場合は、無題の新規文書で起動します（引数なし起動時の
  ファイル選択ウィンドウは今回のマイルストーンでは未対応です）

設定ファイルによる切り替えは今回は未対応です。

## 独立実装であることの宣言

- 原物（PC-98 上で広く使われた各種テキストエディタ、以下「原物」）の
  **逆アセンブルは行っていません**。実装はすべて DOS/BIOS の公開仕様
  （INT 21h の各ファンクション、INT 18h のキーボード入力）と、このリポジトリで
  別途行った実測（`docs/key-measure-*.md`、`docs/bios-key-measure-01.md`、
  `docs/tvram-measure-01.md`、`docs/editor-measure-01.md`、
  `docs/editor-measure-02.md` 等）のみを根拠にしています。
- 原物の**マニュアル本文や画面表示文言は一切使用していません**。タイトル・
  メッセージ・ラベル等の文言はすべてこのプログラム独自の言い回しです。
- カーソル移動キー・BS/DEL による削除・Enter による改行など、キー割り当ての
  多くは WordStar 系に由来する DOS ソフト全般の業界慣行に基づくもので、
  原物固有の実装から持ち込んだものではありません。
- DOS/BIOS 呼び出しのラッパ関数（インラインアセンブラ）・テキストVRAMへの
  直接書き込み層・モーダルダイアログの描画・日英メッセージテーブルの仕組みは、
  同じプロジェクトの `guest/sumire/SUMIRE.C`（ファイラ）から流用しています。
  これは同一プロジェクト・同一著者・同一 MIT ライセンスによる自己流用であり、
  第三者の実装からの流用ではありません。エディタ本体（テキストバッファ・
  行表・カーソル移動・画面描画・キー処理・ファイル入出力）はゼロから
  新規に書き下ろしました。
- 画面のレイアウト（ファンクションキー行の桁位置など）はファイラ「すみれ」
  との見た目の統一のために一部を再利用していますが、これは同一プロジェクト内の
  デザイン上の選択であり、原物の実測値ではありません。
- 本プログラムは原物とは別物であり、原物の作者とは無関係です。

## ビルド方法

`WorkbenchNP2` リポジトリのツールチェーンを使ってビルドします（SmallerC
ベース、16-bit small-model MZ EXE を生成します）。

```
cd WorkbenchNP2
node toolchain/compile.mjs ../guest/tsubaki/TSUBAKI.C -o <出力先>.xdf
```

（パスはリポジトリの配置に合わせて読み替えてください。`compile.mjs` は
入力ファイル1つのみを受け付けます。)

## 現在の実装範囲（第0マイルストーン v0）

- **ファイル操作**
  - 起動時にファイル名を指定すると読み込み、無指定なら無題の新規文書
  - `F2`：上書き保存（無題文書の場合は名前を変えて保存と同じ動作になります）
  - `F3`：名前を変えて保存（入力ダイアログでパスを入力）
  - `F10` / `^Q`：終了。未保存の変更があれば Y/N の確認ダイアログを表示
  - 改行はバッファ内では LF に正規化し、保存時に CRLF へ戻します。CR単独も
    LF として扱います。最終行に改行が無いファイルはそのまま（改行を
    付け足さずに）保存します
  - バッファは 24KB・最大1500行までの単一バッファです（拡張メモリは
    使いません）。容量／行数の上限に達した場合、起動時の読み込みは
    ダイアログを出して中止し、編集中の入力はステータス行へ通知した上で
    無視します（黙って切り捨てることはしません）
- **カーソル移動**（文字単位。全角文字の2セル目には止まりません）
  - `←→↑↓`：1文字/1行移動
  - `ROLL UP` / `ROLL DOWN`：次画面 / 前画面（23行単位）
  - `HOME` / `^A`：行頭
  - `^E`：行末
  - `^T`：文頭
  - `^B`：文末
  - `^G`：指定行番号へ（入力ダイアログ）
  - 縦移動は、移動前の表示桁（目標桁）に最も近い文字境界へ着地します
    （全角文字の途中には決して着地しません）
- **文字入力・編集**
  - 半角文字と全角（SJIS 2バイト）文字の入力に対応
  - `Enter`：改行
  - `TAB`：タブ文字（0x09）を1バイト挿入するだけで、展開はしません
  - `BS`（0x08）：カーソルの前の1文字を削除
  - `^D`：カーソル位置の1文字を削除（`DEL` キー自体のスキャンコードは
    未実測のため、今回は `^D` のみに割り当てています）
  - `^V`：挿入モードと上書きモードの切替。上書きモードで全角文字が
    半角文字を上書きするときは、桁がずれないよう不足分を自動的に
    挿入します
  - `^Y`：カーソル行を丸ごと削除
- **画面**：25行80桁の全セルを毎フレーム描画します（0行目：ステータス行
  （白帯・反転。「ファイル名＋変更マーク＋` - Tsubaki`」または通知／
  行:桁・モード・タブ幅をすべてこの1行に収めています）、1～23行目：
  本文23行、24行目：ファンクションキー行）。ファイル名は元は専用の1行
  （半角罫線の枠）を使っていましたが、本文をもう1行広く使えるよう
  ステータス行へ統合しました。ファイル名と通知は同じフィールド
  （48セル）を共有し、通知が出ていない間は「ファイル名＋変更マーク＋
  ` - Tsubaki`」を、通知が出ている間は通知メッセージを表示します
  （実機実測：ファイル名専用12セルのままだと8.3形式いっぱいの名前を
  1文字編集した瞬間に先頭が欠けたため、通知欄と共有する48セルに
  広げました。通知は次のキー入力で消える一時表示なので、その間
  ファイル名が隠れても支障ありません）。プログラム名は元は左端固定の
  専用欄でしたが、変わるのはファイル名の方でプログラム名は固定という
  性質上、ファイル名の後ろへ` - Tsubaki`として移しました。` - Tsubaki`
  （10セル）は必ず全体を表示し、ファイル名がこの欄（48セルから
  ` - Tsubaki`ぶんを差し引いた残り）に収まらない場合は、末尾の方が
  情報量が多いため先頭側だけを省略し、省略した印として先頭に `<` を
  置きます（` - Tsubaki`は削りません。全角文字の途中では区切りません）。
  80桁を超える行は横スクロールし、カーソルが画面外に出るときだけ
  最小量スクロールします

## 文字コードについての注意（重要）

**`TSUBAKI.C` は CP932（Shift_JIS）でエンコードされており、`g_msgJA[]` の
日本語メッセージは生の CP932 バイト列です。このファイルの文字コードを
UTF-8 などへ変換しないでください。**

このファイルを編集するときは:

- ファイル全体を読み込んで書き戻すような変換的な編集をしない
- どうしても必要な場合はバイト列のまま（Python なら `open(path, 'rb')` /
  `open(path, 'wb')`）扱い、`errors='replace'` は使わない
- 編集の前後で `check.py`（後述）を実行し、CP932 として妥当であること・
  `U+FFFD`（バイト列としては `EF BF BD`）が含まれていないことを確認する
- `grep` はこのファイルに対して使わない（一部のバイトが行終端として
  誤解釈され、存在する行を黙って読み飛ばすことがある）。検索や件数確認は
  Python 等でバイト単位に行う

## 検査スクリプト（check.py）

`check.py` は `TSUBAKI.C` に対して以下を検査します。1つでも失敗すると
非ゼロで終了します（`guest/sumire/check.py` と同じ設計）。

1. `TSUBAKI.C` が CP932 として正しくデコードできる
2. バイト列 `EF BF BD`（`U+FFFD` の UTF-8 表現）が含まれていない
3. `g_msgJA` と `g_msgEN` の要素数が一致する
4. どちらのメッセージテーブルにも空文字列が無い
5. タイトル `g_title`（`g_msgJA`/`g_msgEN` の外にある固定の英語文字列）が
   ステータス行末尾の` - Tsubaki`のプログラム名部分（
   `STATUS_SUFFIX_TITLE_WIDTH`）の幅に収まっている
6. 各メッセージが、実際の使われ方（ステータス行のファイル名／通知の
   共有欄／ステータス行のモード表示／ダイアログ）に応じたセル幅上限に
   収まっているか（日英とも）
7. 画面最下行のファンクションキー表示（`g_fkeyLabel[]`/`g_fkeyCol[]`/
   `g_fkeyHiPos[]`）について、10個のフィールドすべてが `FKEY_FIELD_WIDTH`
   （6セル）幅に収まり、フィールド同士が重ならず、画面幅（80桁）を
   はみ出さないこと
8. ステータス行（行0）の各フィールド幅（`STATUS_SHARED_WIDTH` /
   `STATUS_RIGHT_WIDTH`）の合計がちょうど `VRAM_COLS`（80）になっている
9. `BODY_TOP + BODY_ROWS` が `ROW_FKEY`（24行目）と重ならない
10. すべての通知メッセージ（日英とも）が、ファイル名と共有する
    `STATUS_SHARED_WIDTH` の幅に単独で収まっている（6番の検査と同じ
    上限を、専用の検査としても明示的に確認）

実行方法:

```
cd guest/tsubaki
python3 check.py
```

（省略時は同じディレクトリの `TSUBAKI.C` を検査します。別のパスを検査したい
場合は `python3 check.py <パス>` のように引数で指定できます。)
