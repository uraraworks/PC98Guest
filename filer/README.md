# FILER (PC-98 / FreeDOS(98) directory browser)

これは PC-98 / FreeDOS(98) 向けのファイラです。**開発中**で、現時点ではディレクトリの
一覧表示・カーソル移動・ファイルのマーク・ディレクトリの移動・ファイルの削除・
リネーム・ディレクトリ作成・コピー・移動・終了ができます。

## 表示言語

画面表示は日本語・英語の両方に対応しています。コマンドライン引数で切り替えます。

- `FILER /J` … 日本語（既定。引数を省略した場合も日本語になります）
- `FILER /E` … 英語

設定ファイルによる切り替えは今回は未対応です（今後のマイルストーンで検討）。

## 独立実装であることの宣言

- 原物（NEC PC-98 上で広く使われた各種ファイラ、以下「原物」）の**逆アセンブルは行っていません**。
  実装はすべて DOS の公開仕様（INT 21h の各ファンクション）と、このリポジトリで別途行った
  エスケープシーケンスの実測（`docs/escape-measure-01.md`）のみを根拠にしています。
- 原物の**マニュアル本文や画面表示文言は一切使用していません**。タイトル・メッセージ・
  ラベル等の文言はすべてこのプログラム独自の言い回しです。
- 一部のキー割り当て（矢印キーでの移動、`Q`/`ESC` での終了など）は WordStar 系に由来する
  DOS ソフト全般の業界慣行に基づくもので、原物固有の実装から持ち込んだものではありません。
- 画面のレイアウト（桁位置・行構成）や一部のキー割り当ては機能的な互換性を狙って
  実測に基づき揃えていますが、これは操作感の互換のためであり、原物のコードや文言を
  複製したものではありません。
- 本プログラムは原物とは別物であり、原物の作者とは無関係です。

## ビルド方法

`WorkbenchNP2` リポジトリのツールチェーンを使ってビルドします（SmallerC ベース、
16-bit small-model MZ EXE を生成します）。

```
cd WorkbenchNP2
node toolchain/compile.mjs ../PC98Guest/filer/FILER.C -o <出力先>.xdf
```

(パスはリポジトリの配置に合わせて読み替えてください。`compile.mjs` は入力ファイル1つ
のみを受け付けます。)

## 現在の実装範囲（第4マイルストーン）

第1マイルストーンの機能に加えて:

- **ファイルのマーク**
  - `SPACE`: カーソル位置のファイルをマークして、カーソルを1つ下へ動かす
  - `TAB`: カーソル位置のファイルをマークする（カーソルは動かさない）
  - `HOME`: 全ファイルのマークを ON/OFF でトグルする（1件でもマークがあれば
    全解除、0件なら全マーク）
  - ディレクトリはマークの対象外（`SPACE`/`TAB` を押してもマークは付かず、
    `SPACE` はカーソルだけ下へ動く）
  - マークの印はファイル名の行頭の `*`（色や反転は使用していません）
  - マーク件数はヘッダの Path 行に `マーク:` として表示（マークサイズの合計は
    表示していません。原物はクラスタ単位切り上げでの合計表示でしたが、これは
    原物の実装都合であり本実装では踏襲していません）
- **ディレクトリの移動**
  - カーソルがディレクトリのとき `Enter` でそのディレクトリへ入る
  - `.` と `..` は隠さずそのまま一覧に表示（`..` で親ディレクトリへ戻る）
  - 移動すると Path 表示を更新し、カーソルは先頭へ、マークは全解除
- **ファイルの削除**
  - `D`（または `d`）で削除。対象はマークが1件以上あればマーク全部、
    0件ならカーソル位置の1件（この2つは同じ規則の帰結であり、別々の
    分岐ではありません）
  - 確認ダイアログを表示し、`Y`/`y` で実行、それ以外で中止
  - ディレクトリはマークできないため、削除対象に単独で含まれるのは
    「マーク無しでカーソルがディレクトリ上にある」場合のみ。この場合は
    確認ダイアログを出さず、削除できない旨のエラーを明示して中止する
    （黙ってスキップしない）
  - 削除が成功しても完了メッセージは出さない（一覧の件数が減ることで分かる）
  - 削除に失敗した場合（読み取り専用など）はエラーダイアログを表示する
  - エラーは専用の画面下部行ではなく、操作中のダイアログの中に1行表示し、
    何かキーを押すと閉じる
- **入力ダイアログ（Rename / mKdir 共通部品）**
  - 一覧の上に枠付きのウィンドウを重ねて描画（背後の一覧は消さない）
  - 初期値を入れておける（Rename では元の名前が入る）
  - `Enter` で確定、`ESC` で中止
  - `BS`（`0x08`。PC-98 では `←` も同じコードで来るが、この入力欄では
    常に1文字削除として扱う）で編集
  - 入力可能な長さは最大12文字（DOS の 8.3 名 = ファイル名8文字+ドット+
    拡張子3文字と同じ上限）。それを超える入力は受け付けない
  - エラーは専用行を設けず、同じウィンドウ内に1行表示し、プロンプトと
    入力途中の文字列を残したまま編集を続けさせる（何かキーを押すと消え、
    そのまま打ち直せる）
- **Rename（`R`/`r`）**
  - 対象はカーソル位置の1件のみ（マークは使用しない）
  - `.` と `..` の上では何もしない
  - 入力ダイアログに元の名前を初期値として入れる
  - 実行後は一覧を読み直す。失敗（同名が既にある等）はダイアログ内に
    エラーを表示し、同じ入力欄で打ち直せる
- **mKdir（`K`/`k`）**
  - 入力ダイアログでカレントディレクトリに作る新しいディレクトリ名を
    受け取る（空欄のままの確定はエラーにする）
  - 実行後は一覧を読み直す。失敗（同名が既にある等）はダイアログ内に
    エラーを表示し、同じ入力欄で打ち直せる

- **画面最下行のコマンド表記**
  - 第3マイルストーンまでの「キー:日本語説明」形式（日英でメッセージ全体を
    切り替え、`CMDLINE_WIDTH`（79セル）に収まる範囲でしかキーを列挙できな
    かった）をやめ、原物の流儀（実測）に合わせて英単語のコマンド名を並べ、
    キーになる1文字だけを反転表示する方式にした
  - コマンド名は日英共通の英単語なので、`g_msgJA`/`g_msgEN` には入れず、
    言語に依存しない配列（`g_cmdWords`＝コマンド名、`g_cmdHiPos`＝反転表示
    する文字の位置）として持つ
  - 反転表示は第5マイルストーンからテキストVRAMの属性バイトのb2（反転）
    ビットで行っている（第4マイルストーンまでは `ESC[7m` だった）。下線
    （属性のb3）は描画が4ドット右にずれる不具合があるため使用しない
- **Copy（`C`/`c`）・Move（`M`/`m`）**
  - 対象の決め方は Delete と同じ単一の規則（マークが1件以上あればマーク
    全部、0件ならカーソル位置の1件）。ディレクトリが対象に含まれる場合
    （マーク無しでカーソルがディレクトリ上にある場合のみ起こり得る）は
    黙ってスキップせず、エラーダイアログで中止する
  - 既存の入力ダイアログを再利用し、コピー先/移動先のディレクトリを1段で
    受け取る（ファイル名は元のまま）
  - 同名ファイルが既に存在する場合は原物と異なり（原物は確認なしで拒否・
    実測済み）、1件ずつ `Y`（上書き）/`N`（飛ばす）/`ESC`（操作全体を中止）
    を確認する。黙って上書きせず、黙って飛ばさない
  - Move は同一ドライブなら INT 21h `AH=56h`（リネーム）でその場移動する。
    ドライブが異なる場合はコピーしてから元を削除する（コピーが失敗したら
    元は消さない）
  - コピーは INT 21h の `AH=3Dh`/`3Fh`/`3Ch`/`40h`/`3Eh` を使用し、
    タイムスタンプは `AH=57h`（ファイルの日時取得/設定）で元のものを
    引き継ぐ（原物と同じ）
  - ファイル1件分の読み書きバッファはグローバルに1つだけ持つ（small model
    のデータ領域は64KBに収まる必要があり、一覧が最大1024件ぶんのデータを
    持っているため、スタックに大きな配列は置かない）
  - 途中で失敗した場合は、どのファイルで失敗したかが分かるようにエラーを
    表示する
  - Copy・Move とも成功件数を添えた完了メッセージを表示する（Delete は
    現状維持で完了メッセージを出さない）

- **画面出力のテキストVRAM直書き化（第5マイルストーン）**
  - それまで DOS コンソール（`AH=40h` 経由の ANSI 風エスケープ）で描いて
    いた画面本体を、テキスト VRAM（文字面 `0xA0000`・属性面 `0xA2000`、
    実測: `docs/tvram-measure-01.md`）への直接書き込みに変更した。実機で
    確かめた3つの問題をまとめて解決するため：
    1. それまで使っていた全角の罫線には、実機で使っているフォントに
       字形が無く、何も描かれていなかった（文字コード・属性は正しく
       入っていた）
    2. 再描画のたびに画面全体を `ESC[2J` でクリアしており、カーソル移動
       のたびに全画面がちらついていた
    3. 原物と同じ半角罫線（`0x9C`〜`0x9F` 等、ANK領域）は DOS コンソール
       経由では送れない（`0x81`〜`0x9F` が Shift_JIS 先頭バイトとして
       2バイトにまとめられてしまう。実測: `docs/filer-measure-03.md`）
  - 罫線は原物と同じ半角（1セル1文字）に変更。ヘッダ枠の内側幅
    `BOX_WIDTH` は全角罫線時代の76セルから **78セル** に広がった
    （`check.py` は `#define BOX_WIDTH` を動的に読むため追従は不要）
  - メッセージ（CP932）を VRAM へ書く際は JIS X 0208 へ変換する
    （`sjis_to_jis()`）。実機の画面から実測した16文字のJISコード表と
    突き合わせて全件一致を確認してから実装した
  - 再描画のたびに画面全体をクリアするのをやめ、`g_curChar[]`/
    `g_curAttr[]` に「現在VRAMに実際に入っている内容」を保持しておき、
    セル単位で新しい内容と比較して**変わったセルだけ**実際に書き込む
    （`vram_set_cell()`）。`draw_screen_frame()` は毎回全2000セル分の
    内容を生成し直すが、実際にハードウェアへ書き込まれるのは変化した
    セルだけになるため、画面のどこかが一瞬空白になる瞬間は生じない
  - カーソル行・コマンド行のキー文字強調は、それまでの `ESC[7m`（反転
    表示エスケープ）に代えて、属性バイトのb2（反転）ビットで行う
  - 起動時に一度だけ VRAM 全体をクリアし（DOS起動時の残存表示を消す
    ため）、以降は上記の差分更新のみ行う。終了時も同じ VRAM クリア
    関数で画面を消してから（`ESC[2J`は使わない — この版はDOSコンソール
    側の「現在の色」を一度も設定しないため、それに頼ったクリアは根拠が
    ない）、カーソルを表示状態に戻す
  - ハードウェアの点滅カーソル（`input_dialog()` 編集中のみ表示）の
    位置合わせ・関数キー行の解放/復帰・カーソル表示/非表示は、SJIS/
    半角罫線問題と無関係なASCIIのみのANSIエスケープなので、そのまま
    DOSコンソール経由で送っている

**未実装（今後のマイルストーンで対応予定）:**
- 35件以上のエントリがあるディレクトリでのページング（現状は先頭34件のみ表示）

エントリ数の上限は1024件です。これを超えるディレクトリを開いた場合、超過分は
黙って切り捨てず、その旨を画面（Path行）に表示します。この上限の扱いは
ディレクトリを移動しても変わりません。

## 実装メモ

- ディレクトリ読み取りは DOS INT 21h の AH=1Ah（DTA設定）/ 4Eh（FindFirst）/
  4Fh（FindNext）、カレントディレクトリ取得は AH=47h、ディスク空き容量取得は
  AH=36h を使用しています。いずれも公開されている DOS の標準ファンクションです。
- 画面本体の出力は第5マイルストーンからテキストVRAM（`0xA0000`/`0xA2000`）
  への直接書き込みです。ANSI 風のエスケープシーケンスは、SJIS/半角罫線と
  無関係な用途（点滅カーソルの表示/非表示・位置合わせ、関数キー行の解放/
  復帰）にのみ残っています。SmallerC は small model のためセグメントを
  跨ぐVRAM書き込みは inline asm（`vram_put_raw()`）で行っています。
- SmallerC の 16-bit モードには `long` 型が無いため、ファイルサイズやディスク
  容量などの32ビット値は、上位16ビットと下位16ビットを組にした自前の演算
  （加減算・乗算・10での除算）で扱っています。
- 矢印キーは、IBM PC 系でよくある「`0x00` + 拡張スキャンコード」の2バイト
  方式ではなく、PC-98 の DOS（INT 21h AH=08h）では単独のコントロールコード
  として返ってきます（実機で確認: ↑=0x0B、↓=0x0A、←=0x08、→=0x0C）。
  `^E`/`^X` を上下移動の代替キーとして割り当てていますが、`^S`
  （WordStar 系の慣行では左移動）は割り当てていません。DOS のコンソール
  ドライバが `^S` を XOFF として横取りし、`^Q` を押すまで画面出力が
  止まってしまうことを実機で確認したためです。

## 文字コードについての注意（重要）

**`FILER.C` は CP932（Shift_JIS）でエンコードされており、`g_msgJA[]` の
日本語メッセージは生の CP932 バイト列です。このファイルの文字コードを
UTF-8 などへ変換しないでください。**

過去に一度、このファイル全体を UTF-8 として読み書きするツールにかけた際、
CP932 として妥当だがUTF-8としては不正なバイト列が `U+FFFD`（置換文字）へ
黙って変換され、日本語メッセージが全滅した事例があります。しかもビルドは
通り、英語モード（`/E`）では何の異常も見えなかったため、実機で日本語モード
（既定）を使って初めてクラッシュとして発覚しました（`U+FFFD` は SJIS 解釈で
3セル幅を持つため、ヘッダ枠の想定幅を超えてバッファが溢れる）。

このファイルを編集するときは:
- ファイル全体を読み込んで書き戻すような変換的な編集をしない
- どうしても必要な場合はバイト列のまま（Python なら `open(path, 'rb')` /
  `open(path, 'wb')`）扱い、`errors='replace'` は使わない
- 編集の前後で `check.py`（後述）を実行し、CP932 として妥当であること・
  `U+FFFD`（バイト列としては `EF BF BD`）が含まれていないことを確認する
- `grep` はこのファイルに対して使わない（0x85 等のバイトが行終端として
  誤解釈され、存在する行を黙って読み飛ばすことがある）。検索や件数確認は
  Python 等でバイト単位に行う

## 検査スクリプト（check.py）

`check.py` は `FILER.C` に対して以下を検査します。1つでも失敗すると
非ゼロで終了します。

1. `FILER.C` が CP932 として正しくデコードできる
2. バイト列 `EF BF BD`（`U+FFFD` の UTF-8 表現）が含まれていない
3. `g_msgJA` と `g_msgEN` の要素数が一致する
4. どちらのメッセージテーブルにも空文字列が無い
5. 各メッセージが、実際の使われ方（ヘッダ枠／ダイアログ／実行時に結合される
   フラグメント）に応じたセル幅上限に収まっているか（日英とも）
6. 画面最下行のコマンド表記（`g_cmdWords[]`。第4マイルストーンから
   `g_msgJA`/`g_msgEN` の外に出た言語非依存の構造）を実際の組み立て方と
   同じ手順で再構成し、表示文字数（エスケープシーケンスは含めない）が
   `CMDLINE_WIDTH`（79セル）以内であること

実行方法:

```
cd guest/filer
python3 check.py
```

（省略時は同じディレクトリの `FILER.C` を検査します。別のパスを検査したい
場合は `python3 check.py <パス>` のように引数で指定できます。)
