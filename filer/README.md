# FILER (PC-98 / FreeDOS(98) directory browser)

これは PC-98 / FreeDOS(98) 向けのファイラです。**開発中**で、現時点ではディレクトリの
一覧表示・カーソル移動・終了のみができます（コピー・削除・リネーム等のファイル操作は
未実装です）。

## 表示言語

画面表示は日本語・英語の両方に対応しています。コマンドライン引数で切り替えます。

- `FILER /J` … 日本語（既定。引数を省略した場合も日本語になります）
- `FILER /E` … 英語

設定ファイルによる切り替えは今回は未対応です（今後のマイルストーンで検討）。

## 独立実装であることの宣言

- 原物（NEC PC-98 上で広く使われた各種ファイラ、以下「原物」）の**逆アセンブルは行っていません**。
  実装はすべて DOS の公開仕様（INT 21h の各ファンクション）と、このリポジトリで別途行った
  エスケープシーケンスの実測（`docs/escape-measure-01.md`）のみを根拠にしています。
- 原物の**マニュアル本文や画面表示文言は一切使用していません**。タイトル・メッセージ・
  ラベル等の文言はすべてこのプログラム独自の言い回しです。
- 一部のキー割り当て（矢印キーでの移動、`Q`/`ESC` での終了など）は WordStar 系に由来する
  DOS ソフト全般の業界慣行に基づくもので、原物固有の実装から持ち込んだものではありません。
- 画面のレイアウト（桁位置・行構成）や一部のキー割り当ては機能的な互換性を狙って
  実測に基づき揃えていますが、これは操作感の互換のためであり、原物のコードや文言を
  複製したものではありません。
- 本プログラムは原物とは別物であり、原物の作者とは無関係です。

## ビルド方法

`WorkbenchNP2` リポジトリのツールチェーンを使ってビルドします（SmallerC ベース、
16-bit small-model MZ EXE を生成します）。

```
cd WorkbenchNP2
node toolchain/compile.mjs ../PC98Guest/filer/FILER.C -o <出力先>.xdf
```

(パスはリポジトリの配置に合わせて読み替えてください。`compile.mjs` は入力ファイル1つ
のみを受け付けます。)

## 現在の実装範囲（第1マイルストーン）

- ディレクトリの一覧表示（80x25画面、17行×2カラム=最大34件を1画面に表示）
- ディスクの総容量・使用量・空き容量の表示（3桁カンマ区切り）
- カーソル移動（矢印キー: 上下で行移動、左右でカラム移動）
- `Q` または `ESC` での終了
- カーソル位置のファイル情報（ファイル名・サイズ・日付・属性）の表示

**未実装（今後のマイルストーンで対応予定）:**
- ファイルのコピー・削除・リネーム・ディレクトリ作成などの操作全般
- ディレクトリへの移動（サブディレクトリへの入退出）
- 35件以上のエントリがあるディレクトリでのページング（現状は先頭34件のみ表示）
- ファイルのマーク（複数選択）

エントリ数の上限は1024件です。これを超えるディレクトリを開いた場合、超過分は
黙って切り捨てず、その旨を画面（Path行）に表示します。

## 実装メモ

- ディレクトリ読み取りは DOS INT 21h の AH=1Ah（DTA設定）/ 4Eh（FindFirst）/
  4Fh（FindNext）、カレントディレクトリ取得は AH=47h、ディスク空き容量取得は
  AH=36h を使用しています。いずれも公開されている DOS の標準ファンクションです。
- 画面出力は ANSI 風のエスケープシーケンス（画面クリア・カーソル位置指定・
  文字色）を使用しています。
- SmallerC の 16-bit モードには `long` 型が無いため、ファイルサイズやディスク
  容量などの32ビット値は、上位16ビットと下位16ビットを組にした自前の演算
  （加減算・乗算・10での除算）で扱っています。
- 矢印キーは、IBM PC 系でよくある「`0x00` + 拡張スキャンコード」の2バイト
  方式ではなく、PC-98 の DOS（INT 21h AH=08h）では単独のコントロールコード
  として返ってきます（実機で確認: ↑=0x0B、↓=0x0A、←=0x08、→=0x0C）。
  `^E`/`^X` を上下移動の代替キーとして割り当てていますが、`^S`
  （WordStar 系の慣行では左移動）は割り当てていません。DOS のコンソール
  ドライバが `^S` を XOFF として横取りし、`^Q` を押すまで画面出力が
  止まってしまうことを実機で確認したためです。

## 文字コードについての注意（重要）

**`FILER.C` は CP932（Shift_JIS）でエンコードされており、`g_msgJA[]` の
日本語メッセージは生の CP932 バイト列です。このファイルの文字コードを
UTF-8 などへ変換しないでください。**

過去に一度、このファイル全体を UTF-8 として読み書きするツールにかけた際、
CP932 として妥当だがUTF-8としては不正なバイト列が `U+FFFD`（置換文字）へ
黙って変換され、日本語メッセージが全滅した事例があります。しかもビルドは
通り、英語モード（`/E`）では何の異常も見えなかったため、実機で日本語モード
（既定）を使って初めてクラッシュとして発覚しました（`U+FFFD` は SJIS 解釈で
3セル幅を持つため、ヘッダ枠の想定幅を超えてバッファが溢れる）。

このファイルを編集するときは:
- ファイル全体を読み込んで書き戻すような変換的な編集をしない
- どうしても必要な場合はバイト列のまま（Python なら `open(path, 'rb')` /
  `open(path, 'wb')`）扱い、`errors='replace'` は使わない
- 編集の前後で `check.py`（後述）を実行し、CP932 として妥当であること・
  `U+FFFD`（バイト列としては `EF BF BD`）が含まれていないことを確認する
- `grep` はこのファイルに対して使わない（0x85 等のバイトが行終端として
  誤解釈され、存在する行を黙って読み飛ばすことがある）。検索や件数確認は
  Python 等でバイト単位に行う

## 検査スクリプト（check.py）

`check.py` は `FILER.C` に対して以下を検査します。1つでも失敗すると
非ゼロで終了します。

1. `FILER.C` が CP932 として正しくデコードできる
2. バイト列 `EF BF BD`（`U+FFFD` の UTF-8 表現）が含まれていない
3. `g_msgJA` と `g_msgEN` の要素数が一致する
4. どちらのメッセージテーブルにも空文字列が無い
5. ヘッダ枠に直接置かれるメッセージ（`MSG_TITLE`）が、日本語・英語どちらも
   `BOX_WIDTH` セル幅に収まる

実行方法:

```
cd guest/filer
python3 check.py
```

（省略時は同じディレクトリの `FILER.C` を検査します。別のパスを検査したい
場合は `python3 check.py <パス>` のように引数で指定できます。)
