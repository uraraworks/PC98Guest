# Sumire (すみれ), a file manager for PC-98 / FreeDOS(98)

**Sumire（すみれ）**は PC-98 / FreeDOS(98) 向けのファイラです。
以前は仮名として「FILER」を名乗っていましたが、正式名称を Sumire/すみれ に改名しました
（ソースは `SUMIRE.C`、実行ファイルは `SUMIRE.EXE` です）。**開発中**で、現時点では
ディレクトリの一覧表示・カーソル移動・ファイルのマーク・ディレクトリの移動・
ファイルの削除・リネーム・ディレクトリ作成・コピー・移動・プログラムの実行（eXec）・
内蔵ビューアでのテキスト閲覧・終了ができます。

## 表示言語

画面表示は日本語・英語の両方に対応しています。コマンドライン引数で切り替えます。

- `SUMIRE /J` … 日本語（既定。引数を省略した場合も日本語になります）
- `SUMIRE /E` … 英語

設定ファイルによる切り替えは今回は未対応です（今後のマイルストーンで検討）。

## 独立実装であることの宣言

- 原物（NEC PC-98 上で広く使われた各種ファイラ、以下「原物」）の**逆アセンブルは行っていません**。
  実装はすべて DOS の公開仕様（INT 21h の各ファンクション）と、このリポジトリで別途行った
  エスケープシーケンスの実測（`docs/escape-measure-01.md`）のみを根拠にしています。
- 原物の**マニュアル本文や画面表示文言は一切使用していません**。タイトル・メッセージ・
  ラベル等の文言はすべてこのプログラム独自の言い回しです。
- 一部のキー割り当て（矢印キーでの移動、`Q`/`ESC` での終了など）は WordStar 系に由来する
  DOS ソフト全般の業界慣行に基づくもので、原物固有の実装から持ち込んだものではありません。
- 画面のレイアウト（桁位置・行構成）や一部のキー割り当ては機能的な互換性を狙って
  実測に基づき揃えていますが、これは操作感の互換のためであり、原物のコードや文言を
  複製したものではありません。
- 本プログラムは原物とは別物であり、原物の作者とは無関係です。

## ビルド方法

`WorkbenchNP2` リポジトリのツールチェーンを使ってビルドします（SmallerC ベース、
16-bit small-model MZ EXE を生成します）。

```
cd WorkbenchNP2
node toolchain/compile.mjs ../guest/sumire/SUMIRE.C -o <出力先>.xdf
```

(パスはリポジトリの配置に合わせて読み替えてください。`compile.mjs` は入力ファイル1つ
のみを受け付けます。)

## 現在の実装範囲（第7マイルストーンまで）

第1マイルストーンの機能に加えて:

- **ファイルのマーク**
  - `SPACE`: カーソル位置のファイルをマークして、カーソルを1つ下へ動かす
  - `TAB`: カーソル位置のファイルをマークする（カーソルは動かさない）
  - `HOME`: 全ファイルのマークを ON/OFF でトグルする（1件でもマークがあれば
    全解除、0件なら全マーク）
  - ディレクトリはマークの対象外（`SPACE`/`TAB` を押してもマークは付かず、
    `SPACE` はカーソルだけ下へ動く）
  - マークの印はファイル名の行頭の `*`（色や反転は使用していません）
  - マーク件数はヘッダの Path 行に `マーク:` として表示（マークサイズの合計は
    表示していません。原物はクラスタ単位切り上げでの合計表示でしたが、これは
    原物の実装都合であり本実装では踏襲していません）
- **ディレクトリの移動**
  - カーソルがディレクトリのとき `Enter` でそのディレクトリへ入る
  - `.` と `..` は隠さずそのまま一覧に表示（`..` で親ディレクトリへ戻る）
  - 移動すると Path 表示を更新し、カーソルは先頭へ、マークは全解除
- **ファイルの削除**
  - `D`（または `d`）で削除。対象はマークが1件以上あればマーク全部、
    0件ならカーソル位置の1件（この2つは同じ規則の帰結であり、別々の
    分岐ではありません）
  - 確認ダイアログを表示し、`Y`/`y` で実行、それ以外で中止
  - ディレクトリはマークできないため、削除対象に単独で含まれるのは
    「マーク無しでカーソルがディレクトリ上にある」場合のみ。この場合は
    確認ダイアログを出さず、削除できない旨のエラーを明示して中止する
    （黙ってスキップしない）
  - 削除が成功しても完了メッセージは出さない（一覧の件数が減ることで分かる）
  - 削除に失敗した場合（読み取り専用など）はエラーダイアログを表示する
  - エラーは専用の画面下部行ではなく、操作中のダイアログの中に1行表示し、
    何かキーを押すと閉じる
- **入力ダイアログ（Rename / mKdir 共通部品）**
  - 一覧の上に枠付きのウィンドウを重ねて描画（背後の一覧は消さない）
  - 初期値を入れておける（Rename では元の名前が入る）
  - `Enter` で確定、`ESC` で中止
  - `BS`（`0x08`。PC-98 では `←` も同じコードで来るが、この入力欄では
    常に1文字削除として扱う）で編集
  - 入力可能な長さは最大12文字（DOS の 8.3 名 = ファイル名8文字+ドット+
    拡張子3文字と同じ上限）。それを超える入力は受け付けない
  - エラーは専用行を設けず、同じウィンドウ内に1行表示し、プロンプトと
    入力途中の文字列を残したまま編集を続けさせる（何かキーを押すと消え、
    そのまま打ち直せる）
- **Rename（`R`/`r`）**
  - 対象はカーソル位置の1件のみ（マークは使用しない）
  - `.` と `..` の上では何もしない
  - 入力ダイアログに元の名前を初期値として入れる
  - 実行後は一覧を読み直す。失敗（同名が既にある等）はダイアログ内に
    エラーを表示し、同じ入力欄で打ち直せる
- **mKdir（`K`/`k`）**
  - 入力ダイアログでカレントディレクトリに作る新しいディレクトリ名を
    受け取る（空欄のままの確定はエラーにする）
  - 実行後は一覧を読み直す。失敗（同名が既にある等）はダイアログ内に
    エラーを表示し、同じ入力欄で打ち直せる

- **画面最下行のコマンド表記（第6マイルストーンで原物のファンクションキー
  表示に作り直し）**
  - 第4・第5マイルストーンでは英単語のコマンド名を並べ、キーになる1文字
    だけを反転表示していたが、これは原物の実際の最下行（**ファンクション
    キーの割り当て表示**）ではなかった。実機（原物 FD 3.13(98) 版）を実測
    （`docs/filer-measure-05.md`）した結果に基づき作り直した
  - 6セル幅のフィールドが10個（F1〜F10）、開始桁 `g_fkeyCol[]` は
    `{4, 11, 18, 25, 32, 42, 49, 56, 63, 70}`（F5とF6の間だけ4セル空く。
    それ以外は1セル空き）で、実測値そのまま
  - `g_fkeyLabel[]` が各フィールドのラベル（空文字列＝その位置は予約
    のみで未実装。原物にあった Sort/Find/Tree 等はこの
    プログラムでは実装していないため、名前を出さず空欄にしてある。
    eXec は第7マイルストーン、Logdsk は第12マイルストーンで実装済み）、`g_fkeyHiPos[]` がラベル中の
    「実際のキーになる1文字」の位置
  - 属性は実測どおり2種類使い分ける：ラベル全体を `ATTR_FKEY_LABEL`
    (`0xA5`＝反転＋色101) にし、キーになる1文字だけ `ATTR_FKEY_KEY`
    (`0xC5`＝反転＋色110＝黄) に変える。**ラベル全体を反転させ、キー
    文字だけ色を変える**のが原物の作法で、第4/5マイルストーンの
    「キー文字だけ反転」とは異なる
  - 配置は原物と同じ位置に揃えた：**F3=Copy、F4=Delete、F5=Rename**。
    残り（Move・mKdir・Quit）は空いている位置へ：**F6=Move、F7=mKdir、
    F10=Quit**。**F2=eXec も原物と同じ位置に揃えた**（第7マイルストーン、
    後述）。**F1=Logdsk も原物と同じ位置**（第12マイルストーン、後述）。
    F8・F9 はこのプログラムで未実装のコマンドのための予約枠（空欄）
  - `Arrow:move SP/Tab:mark HOME:all Enter:open` のような操作説明は
    最下行から外した（原物の最下行はキーの説明ではなく機能の場所を
    示すものだったため）。該当する操作（矢印移動・SPACE/TABマーク・
    HOME全マーク・Enterで開く）自体は変更なく引き続き有効
  - 既存の文字キー（`C`/`M`/`D`/`R`/`K`/`Q`/`X`）も従来どおり使える。
    ファンクションキーは追加の入口であり、置き換えではない
  - **ファンクションキーの読み取り**（第6マイルストーン当時）: PC-98 の
    DOS（`AH=08h`）はファンクションキーを `0x1B`（ESC）+ 英字1文字の
    2バイトで返す（実測: `docs/filer-measure-05.md`）。ところが `ESC`
    キー単独も `0x1B` の1バイトだけを返すため、`0x1B` を読んだ時点では
    ESC単独なのかファンクションキーの先頭バイトなのか区別できず、
    `AH=0Bh` で続きのバイトの有無を見て分岐していた。**第10マイル
    ストーンで INT 18h へ移行し、この二段階判定は不要になった**
    （後述）
  - 反転表示は第5マイルストーンからテキストVRAMの属性バイトのb2（反転）
    ビットで行っている。下線（属性のb3）は描画が4ドット右にずれる
    不具合があるため使用しない
- **Copy（`C`/`c`）・Move（`M`/`m`）**
  - 対象の決め方は Delete と同じ単一の規則（マークが1件以上あればマーク
    全部、0件ならカーソル位置の1件）。ディレクトリが対象に含まれる場合
    （マーク無しでカーソルがディレクトリ上にある場合のみ起こり得る）は
    黙ってスキップせず、エラーダイアログで中止する
  - 既存の入力ダイアログを再利用し、コピー先/移動先のディレクトリを1段で
    受け取る（ファイル名は元のまま）
  - 同名ファイルが既に存在する場合は原物と異なり（原物は確認なしで拒否・
    実測済み）、1件ずつ `Y`（上書き）/`N`（飛ばす）/`ESC`（操作全体を中止）
    を確認する。黙って上書きせず、黙って飛ばさない
  - Move は同一ドライブなら INT 21h `AH=56h`（リネーム）でその場移動する。
    ドライブが異なる場合はコピーしてから元を削除する（コピーが失敗したら
    元は消さない）
  - コピーは INT 21h の `AH=3Dh`/`3Fh`/`3Ch`/`40h`/`3Eh` を使用し、
    タイムスタンプは `AH=57h`（ファイルの日時取得/設定）で元のものを
    引き継ぐ（原物と同じ）
  - ファイル1件分の読み書きバッファはグローバルに1つだけ持つ（small model
    のデータ領域は64KBに収まる必要があり、一覧が最大1024件ぶんのデータを
    持っているため、スタックに大きな配列は置かない）
  - 途中で失敗した場合は、どのファイルで失敗したかが分かるようにエラーを
    表示する
  - Copy・Move とも成功件数を添えた完了メッセージを表示する（Delete は
    現状維持で完了メッセージを出さない）

- **画面出力のテキストVRAM直書き化（第5マイルストーン）**
  - それまで DOS コンソール（`AH=40h` 経由の ANSI 風エスケープ）で描いて
    いた画面本体を、テキスト VRAM（文字面 `0xA0000`・属性面 `0xA2000`、
    実測: `docs/tvram-measure-01.md`）への直接書き込みに変更した。実機で
    確かめた3つの問題をまとめて解決するため：
    1. それまで使っていた全角の罫線には、実機で使っているフォントに
       字形が無く、何も描かれていなかった（文字コード・属性は正しく
       入っていた）
    2. 再描画のたびに画面全体を `ESC[2J` でクリアしており、カーソル移動
       のたびに全画面がちらついていた
    3. 原物と同じ半角罫線（`0x9C`〜`0x9F` 等、ANK領域）は DOS コンソール
       経由では送れない（`0x81`〜`0x9F` が Shift_JIS 先頭バイトとして
       2バイトにまとめられてしまう。実測: `docs/filer-measure-03.md`）
  - 罫線は原物と同じ半角（1セル1文字）に変更。ヘッダ枠の内側幅
    `BOX_WIDTH` は全角罫線時代の76セルから **78セル** に広がった
    （`check.py` は `#define BOX_WIDTH` を動的に読むため追従は不要）
  - メッセージ（CP932）を VRAM へ書く際は JIS X 0208 へ変換する
    （`sjis_to_jis()`）。実機の画面から実測した16文字のJISコード表と
    突き合わせて全件一致を確認してから実装した
  - 再描画のたびに画面全体をクリアするのをやめ、`g_curChar[]`/
    `g_curAttr[]` に「現在VRAMに実際に入っている内容」を保持しておき、
    セル単位で新しい内容と比較して**変わったセルだけ**実際に書き込む
    （`vram_set_cell()`）。`draw_screen_frame()` は毎回全2000セル分の
    内容を生成し直すが、実際にハードウェアへ書き込まれるのは変化した
    セルだけになるため、画面のどこかが一瞬空白になる瞬間は生じない
  - カーソル行・コマンド行のキー文字強調は、それまでの `ESC[7m`（反転
    表示エスケープ）に代えて、属性バイトのb2（反転）ビットで行う
  - 起動時に一度だけ VRAM 全体をクリアし（DOS起動時の残存表示を消す
    ため）、以降は上記の差分更新のみ行う。終了時も同じ VRAM クリア
    関数で画面を消してから（`ESC[2J`は使わない — この版はDOSコンソール
    側の「現在の色」を一度も設定しないため、それに頼ったクリアは根拠が
    ない）、カーソルを表示状態に戻す
  - ハードウェアの点滅カーソル（`input_dialog()` 編集中のみ表示）の
    位置合わせ・関数キー行の解放/復帰・カーソル表示/非表示は、SJIS/
    半角罫線問題と無関係なASCIIのみのANSIエスケープなので、そのまま
    DOSコンソール経由で送っている

- **表示の改善3件（実測 `docs/filer-measure-03.md`/`filer-measure-05.md` に基づく）**
  - **ファンクションキーのラベルはフィールド全体を反転**：それまでは
    `draw_cmdline()` がラベルの文字がある部分だけを反転させていたが、
    原物は6セル幅のフィールド全体（余白の空白セルも含む）を反転させて
    いる（実測: `eXec` の6セルすべてが `a5 a5 c5 a5 a5 a5`）。パディング
    の空白セルにも `ATTR_FKEY_LABEL` を塗るよう変更。未実装（ラベルが
    空）のフィールドはこれまでどおり塗らない
  - **ヘッダ1行目に縦の区切り罫線を追加**：`合計:…使用:…空き:…` の間に
    半角の縦線（`0x96`）を2本入れた。総合計/使用量フィールドを
    `DISK_FIELD_WIDTH`（25セル）に固定幅パディングし、区切りの桁
    （`DISK_SEP_COL1`/`DISK_SEP_COL2`）が毎フレーム同じ位置に来るように
    した上で、0行目（上辺）の同じ桁を `0x91`、2行目（区切り線）の同じ
    桁を `0x90`（いずれも接合文字、実測）に差し替え、縦線が上下で
    途切れないようにした
  - **右上に日時表示**：0行目の右端に `YY-MM-DD HH:MM:SS`（17セル）を
    表示。日付は INT 21h `AH=2Ah`、時刻は `AH=2Ch`（いずれも `dos_getdate()`/
    `dos_gettime()`）で取得する。秒を進めるため、`main()` のメインループを
    `dos_getch()`（`AH=08h`、キー入力までブロックする）で待つのをやめ、
    `dos_kbhit()`（`AH=0Bh`）でキー入力の有無をポーリングしながら、
    入力が無い間は `draw_title_row()` を呼んで時計だけ再描画する形に
    変更した（差分更新のおかげで実際に変化した桁しか書き込まれない）。
    ポーリング間隔は `IDLE_POLL_SPIN` の固定回数busy-waitで簡易的に
    抑制している（実機的な「N ティック待って戻る」プリミティブが
    無いための単純化）
  - 日時表示の分だけタイトルの表示幅が縮む（`BOX_WIDTH` からクロック
    17セル＋区切り1セル＋タイトル自身の装飾4セルを差し引いた分が
    `MSG_TITLE` の実効上限。`check.py` はこの計算式を `#define` から
    動的に導出する）ため、タイトル文言を短縮した。マイルストーン表記は
    タイトルからは削除し、README側にのみ残す

- **改名・表示修正・eXec 追加（第7マイルストーン）**
  - **Sumire/すみれへ改名**：ソース `FILER.C` を `SUMIRE.C` に、フォルダ
    `filer/` を `sumire/` に改名した（タイトルも「すみれ - ディレクトリ
    ビューア」/「Sumire - Directory viewer」に変更）
  - **0行目26桁目のちらつきを修正**：実機実測で、0行目（タイトル行）の
    ディスク行区切りの真上にあたる桁（`DISK_SEP_COL1`）が空白(`0x20`)と
    接合文字(`0x91`)の間で毎フレーム振動していた（14サンプル中空白5回・
    接合9回）。原因は `draw_title_row()` が「まずダッシュで埋める→
    最後に無条件で接合文字に上書きする」という2段階構成になっており、
    最終的な見た目は同じでも**同じセルに毎フレーム2回、異なる値を
    書き込んでいた**こと（VRAMの差分更新は「直前に書いた値と同じか」
    しか見ないため、この2回の書き込みはどちらも実際にハードウェアへ
    出る）。修正は、行全体を単一のループで1セルずつ確定させる形に
    書き直し、接合文字はダッシュで埋める段そのものの中でだけ（＝
    タイトル文字や日時が実際に占めている桁を除いて）書き込むように
    した。これで1セルにつき1フレーム最大1回しか書き込まれなくなり、
    値が収束した後は差分更新で書き込み自体が起きなくなる
  - **ディスク合計行の数値を右詰めに変更、単位サフィックスを撤去**：
    原物の実測（`Total:   128,520,192` のような書式）に合わせ、各欄の
    数値を右詰め（右端に1桁ぶんの空白を残す）にし、「バイト」/
    `bytes` の単位表示をやめた（ラベルで自明なため）。`DISK_FIELD_WIDTH`
    は単位サフィックス分が要らなくなった分だけ縮小した（25→20セル）。
    右詰め自体は新設のヘルパー `sappend_field_rj()` で行う
  - **F2/eXec（プログラムの実行）を追加**：カーソル位置のファイル
    （マークは使わない）を実行する。対象は拡張子が `COM`/`EXE` の
    ものだけで、それ以外は黙って何もせず終わるのではなく、専用の
    エラーダイアログを出す。実行は INT 21h `AH=4Bh`（EXEC、load and
    execute）。このプログラムの MZ ヘッダは minalloc=maxalloc になって
    おり、起動時に確保するメモリを実際に使う分だけに抑えているため
    （実測済み）、子プロセス用の空きメモリが残っている。実行後は画面が
    子プロセスに書き換えられている前提で、「実行を終了しました（何か
    キーを押してください）」ダイアログを出してからキー入力を待ち、
    その後 `vram_shadow_init()` でVRAM差分更新の記憶（現在VRAMに
    実際に入っている内容の記録）を丸ごと破棄してから画面全体を
    再描画する（記憶を残したままだと、子プロセスが書き換えたセルの
    うち偶然直前の内容と一致するものが再描画で書き込まれず、ゴミが
    残り続ける）。実行に失敗した場合も同様にエラーダイアログを出す。
    キー割り当ては原物と同じ位置（F2）・同じラベル（`eXec`、`X`が
    実際のキー）で、文字キー `X`/`x` からも直接呼べる

- **F2/eXec後の画面残骸修正、実測に基づく配色対応（第8マイルストーン）**
  - **F2実行から戻ったときの画面残骸を修正**：実機で `F2` から
    `COMMAND.COM` を実行し `EXIT` で戻ると、ファンクションキー行が
    23行目・24行目に二重に描かれる、一覧の右側にゴミ文字が残る、
    最下行に子シェルのプロンプトが残る、という3つの症状が出ていた。
    原因は、子プロセスの出力で画面が1行スクロールし、こちらが描いた
    内容が上へずれたこと。`vram_shadow_init()` でVRAM差分更新の記憶を
    破棄しても、`draw_screen()`/`draw_dialog()` はこのプログラムが
    普段使うセルしか塗り直さないため、23行目（一覧と最下行の間、誰も
    描画しない行）や一覧2カラムの間の1桁・画面最終桁のような「普段
    誰も書き込まないセル」にずれて残った内容は消えない。修正は、
    `vram_shadow_init()` の直後に `vram_clear_all()` を呼び、25行×80桁
    全セルを実際に空白で塗り直してから、通常どおり `draw_dialog()`/
    `draw_screen()` で上書きするようにした
  - **配色を実測（`docs/filer-measure-06.md`）に合わせた**：属性面
    （`0xA2000`）を直接読んで得た配色規則を反映した
    - 罫線（枠・区切り）とヘッダのラベル（`合計:`/`使用:`/`空き:`/
      `パス=`/`情報:`）は水色（`0xA1`）
    - タイトルと右上の日時は黄（`0xC1`）
    - ヘッダの値（パス・ファイル名・数値）は白（`0xE1`）
    - 一覧はエントリの種別で色分け：ディレクトリは水色（`0xA1`）、
      通常のファイルは黄（`0xC1`）、システム属性または隠し属性を持つ
      ファイルはマゼンタ（`0x61`）
    - **カーソル行は色を変えず、反転ビット（`0x04`）を立てるだけ**
      （実測でカーソル行 `0x65`・非カーソル行 `0x61` は同じ色だった）。
      これまでの「カーソル行=黄／他=白」という色の上書き方式は廃止
    - マーク（行頭の `*`）は引き続き色や反転を使わない。マーク行と
      カーソル行が重なった場合はカーソルの反転がそのまま乗るだけ

- **内蔵ビューアの追加（第9マイルストーン）**
  - 一覧で `Enter` を押したときの挙動を拡張した：ディレクトリは従来どおり
    移動、拡張子が `COM`/`EXE` のファイルは何もしない（実行は従来どおり
    `F2`/`X`）、それ以外のファイルは新設の内蔵ビューアを開く
  - 画面構成・操作・タブ/折り返し/改行有無の扱いは、原物 FD 3.13(98)版の
    内蔵ビューアを実機実測した結果（`docs/filer-measure-07.md`）に
    合わせた：
    - 0行目 `File name: <フルパス>`（反転）＋ `Line No: <先頭行>/<総行数>`
      （ラベル水色・値黄。既存の `ATTR_REV`/`ATTR_LABEL`/`ATTR_TITLE` を
      流用）、1行目は空、2〜23行目がファイル内容（22行）、24行目は
      ビューア用の簡易ヒント行（`ESC:一覧へ戻る`/`ESC: back to list`）
    - `↓`/`↑` で1行、`HOME` で先頭へ、`ESC` で一覧へ戻る
    - タブは幅8で展開、80桁を超える行は（切り捨てずに）折り返し、
      全角文字の途中では折り返さない、行末には改行の有無に応じて
      全角の改行記号を出す（改行のない最終行には出さない）。行数は
      折り返し後の表示行で数える
    - **`ROLL UP`/`ROLL DOWN` は第11マイルストーンで実装した**（実測時点
      では未実測だったため見送っていたが、その後 `docs/bios-key-measure-01.md`
      でスキャンコードを実測できたため対応。詳細は後述の第11マイルストーン
      の節を参照）
    - 改行記号の具体的な字形（全角下矢印、CP932 `0x81 0xAB`）は実測値
      ではなく本実装独自の選択。実測できているのは「何らかの全角の印が
      出る」ことだけで、原物の字形そのものは確認していない
  - **メモリ設計**：ファイルは一切まるごと読み込まない。small model の
    データ領域は64KBしかなく、一覧1024件分のバッファやVRAMシャドウが
    既に大きな部分を占めているため、ビューアは512バイトの読み取り
    バッファ経由でファイルを前から順に読み進めるだけで、行オフセットの
    索引はどこにも保持しない
    - 総行数は開いたときに一度だけファイル全体を走査して数える
      （`view_count_lines()`）。1バイトずつではなく読み取りバッファ
      経由で読むため、巨大なファイルでも固まらない
    - 上/下/HOME による表示行の移動は、索引を持たない代わりに
      毎回ファイルを先頭から開き直し、目的の行の手前まで読み飛ばして
      から表示する（`view_goto_line()`）。コストは目的の行番号に
      比例するだけで（ファイルサイズそのものには比例しない）、
      必ず終了する。ページ送りのたびに毎回先頭から読み直す分、
      ファイルの奥深くまでスクロールした状態での連続操作は
      そのぶん遅くなるトレードオフを許容している
  - **つばき（テキストエディタ）との連携について**：将来的にビューアから
    「編集」でつばきを起動できるようにする構想があるが、つばきはまだ
    存在しないため、今回はその出口（編集コマンド）は実装していない

- **タイトルの中央寄せ、キー入力のBIOS(INT 18h)化（第10マイルストーン）**
  - **タイトルを `<< >>` で囲み中央寄せに変更**：原物の0行目は罫線の中に
    タイトルが中央寄せで置かれている。それまでの「`--` + 左寄せタイトル
    + ダッシュで右まで埋める」形から、`<< タイトル >>` を用意した幅の
    中で中央寄せし、両側を横罫線で埋める形に変更した（日英の切替・
    右上の日時表示・0行目が1回の関数呼び出しで全セルを確定させる
    構造は変更なし。ちらつき対策のため接合文字の差し込みは左右2本の
    ダッシュ塗りループそれぞれの中で行う）
  - **キー入力を DOS(INT 21h AH=08h) から BIOS(INT 18h) へ移行**：DOS
    経由では原物と同じにできない項目が3件、すべて実測で確認されていた
    （`docs/dos-key-measure-01.md`）：
    - `^S`（0x13）が DOS コンソールに XOFF として横取りされ、画面出力が
      止まる
    - 内蔵ビューアの `ROLL UP`/`ROLL DOWN` が `AH=08h` では1バイトも
      返らない
    - 同じく `HELP` も返らない
    - 画面出力は第5マイルストーンで既に VRAM 直書きへ移行済みで、DOS
      のコンソールを使っていなかった。入力も移せばこれら3件がまとめて
      解決する
    - `dos_getch()`/`dos_kbhit()` を内部実装だけ INT 18h AH=00h/01h に
      差し替え、関数名・呼び出し側（約30箇所）は変更していない。
      `AH=00h` は AH=スキャンコード・AL=文字コードを返す
      （`docs/key-measure-01.md`/`docs/key-measure-02.md`）ため、AL が
      非ゼロならそれまでどおりの値として扱い、ゼロのときだけスキャン
      コードで矢印キー・HOME・ファンクションキーを判別する
    - ファンクションキーは INT 18h ではスキャンコード（`0x62`〜`0x6B`）
      で直接分かるため、旧来の「ESC を読んだ直後に `dos_kbhit()` で
      続きバイトの有無を見る」二段階判定が不要になり、`main()` の
      分岐から削除した。**ESC単独での中止は従来どおり維持**（INT 18h
      でも ESC キーは AL=0x1B を返すため、この経路はそのまま動く）
    - `←` と `BS` は DOS では同じコード（`0x08`）で来ていたが、INT 18h
      では別々のスキャンコード（`←`=0x3B、BS=0x0E）になる。ただし
      `dos_getch()` は `←` のスキャンコードを見つけても意図的に同じ
      `KEY_LEFT`（`0x08`）値へ変換して返しており、各呼び出し側の
      分岐（一覧移動では左移動・入力ダイアログではBSとして扱う）は
      DOS時代と全く同じ動きのまま変わっていない
    - **今回割り当てを見送ったキー**：`HELP`(0x3F)・`INS`(0x38)・`DEL`(0x39)
      はスキャンコードの値自体は `docs/dos-key-measure-01.md`/WebNP2の
      キーマップから分かっているが、この一式のキー自体は今回のプログラムで
      まだ機能を割り当てていない。`ROLL UP`(0x36)/`ROLL DOWN`(0x37) は
      第11マイルストーンで実測・実装済み（後述）

- **タイトルの英語固定、内蔵ビューアの ROLL UP/ROLL DOWN（第11マイルストーン）**
  - **タイトルを日英切替の対象から外し、常に英語表記に固定**：利用者の
    指定により、画面上部のタイトル（`<< Sumire - Directory viewer >>`、
    中央寄せの書式は変更なし）は日本語モードでもこの英語表記のまま出す
    ようにした。**タイトル以外の文言（`パス=`/`情報:`/`合計:`/各種
    ダイアログ・エラー等）は引き続き日英切替のまま**で、今回は変更して
    いない
    - 実装としては、タイトルを `g_msgJA`/`g_msgEN`（言語表）から切り離し、
      `g_title`（固定の英語 C 文字列）という独立した変数にした。この
      切り離し方は、最下行のファンクションキー表示 `g_fkeyLabel[]` が
      既に「言語に依らない C データ」として言語表の外に置かれているのと
      同じ扱いである
    - `check.py` もこれに追従：タイトルのセル幅検査（ヘッダ枠内の日時表示
      分を差し引いた実効幅に収まるか）は無くしておらず、`g_title` 単体に
      対して行うよう変更した（`g_msgJA`/`g_msgEN` 側の検査からは
      `MSG_TITLE` を削除し、残りの添字を詰め直した）
  - **内蔵ビューアに `ROLL UP`/`ROLL DOWN` を割り当てた**：第10マイルス
    トーンの時点ではスキャンコードが未実測のため見送っていたが、
    `docs/bios-key-measure-01.md` で `ROLL UP`=`0x36`・`ROLL DOWN`=`0x37`
    （いずれも文字コードは `0x00`）が実測できたため対応した
    - 動作は原物の実測（`docs/filer-measure-07.md`）どおり：`ROLL UP` は
      画面の内容行数と同じ22行（`VIEW_CONTENT_ROWS`）先へ進み、総行数を
      超えない。`ROLL DOWN` は22行戻り、先頭（1行目）より前には行かない
    - **一覧側（ファイラ本体）にはこの2キーを割り当てていない。** 一覧の
      ページ切り替えはこのプログラムにまだ実装が無く、原物での挙動も
      未実測のため（引き続き下記「未実装」に記載）
    - `HELP`（`0x3F`）は今回割り当てていない。ヘルプ画面自体をこの
      プログラムが持たないため

- **ドライブ変更（Logdsk。`L` または `F1`）** — 第12マイルストーン。
  ダイアログでドライブ名を1文字入力する（`A` でも `A:` でも可、大小問わず）。
  - **有効性は INT 21h AH=0Eh の戻り値では判定できない**（存在しない
    ドライブを渡しても何も報告しない）。先に AH=36h を投げて `0xFFFF` が
    返らないことを確かめ、切り替えた後にも AH=19h で実際に移ったことを
    確認する
  - エラーは専用行ではなくダイアログの中に出し、入力を継続させる
    （原物に対する実測 `docs/filer-measure-04.md` の作法に合わせた）
  - 成功したらパス・一覧・カーソルを入れ替え、**マークは必ず捨てる**
    （前のドライブのファイルを指しているため）
  - 移動先は「そのドライブについて DOS が覚えているカレント
    ディレクトリ」になる。このプログラムはディレクトリ移動を
    自分のパス文字列の操作だけで行い DOS のカレントを変えないので、
    実際にはたいていそのドライブのルートになる
  - 実機での確認は `docs/sumire-verify-01.md`

- **ダイアログのちらつきを構造的に防ぐ「覆い」**（第12マイルストーン）
  - ちらつきの正体は「同じセルが1フレームの中で2回書かれること」（背景 → 前面）です。
    画面は2回目が来る前の状態も表示してしまいます
  - `overlay_show()` で矩形を宣言している間、`vram_set_cell()` は**覆いの内側への
    書き込みを、覆い自身が描いている間以外は無視します**。背景を描き直す経路が
    どこにあってもダイアログのセルには届きません
  - 覆いを閉じるのは `main()` のキー処理の末尾**1か所だけ**です。モーダルは必ず
    1回のキー処理の中で開いて閉じるので、経路ごとに閉じ忘れることが起きません
  - ダイアログの高さはエラー行を常設して固定してあります（高さが変わると
    「さっきまで枠だったセルを背景へ戻す」処理が必要になり、そこが次の
    二重書きの温床になるため）
  - **「背景を描き直す経路を通らないようにする」という直し方はしません。**
    それは経路ごとの対策で、経路が増えるたびに再発します（実際に3度出ました）

- **F2/eXec の引数入力と、実行前後の画面・カーソルの後始末**（第13マイルストーン）
  - **引数入力ダイアログを追加**：`F2`/`X` で拡張子の確認を通ったら、
    **カーソル位置のファイル名を入れた状態**で入力ダイアログを開きます。
    引数が要らなければそのまま `Enter`、必要なら名前の後ろに続けて打ちます
    （`ESC` で実行の取りやめ）。入力行は「最初の語＝プログラム名／残り＝
    引数」に分け、引数は**コマンドテール（PSP:80h）**として子プロセスへ
    渡します。DOS プロンプトから起動したときと同じく、引数があるときは
    区切りの空白1つをテールの先頭に含めます（`PSP:81h` を自分で解析する
    プログラムの多くがこれを前提にしているため）。FCB1/FCB2 は従来どおり
    空のままです
  - 名前が空、または `COM`/`EXE` でなければ、ダイアログの中にエラーを
    出して入力を続けさせます（Rename/Logdsk と同じ作法）。名前を打ち替えた
    場合は、カーソル位置ではなく**打たれたほうを実行**します
  - **実行中にカーソル行の反転が残る問題を修正**：子プロセスへ渡す前に
    25行×80桁を空白で塗り、テキストカーソルをホーム位置へ戻すように
    しました。従来はこのプログラムの画面（反転したカーソル行を含む）が
    そのまま残り、子プロセスの出力と混ざって見えていました。入力ダイアログの
    「覆い」も、この1か所だけは明示的に閉じてからクリアします（覆いが
    残っているとクリアがその内側に届かず、ダイアログの枠が子プロセスの
    画面に残るため）
  - **実行のたびに出力が2行ずつ下へずれる問題を修正**：原因は同じで、
    DOS のテキストカーソル位置が引き継がれたままだったこと。出力の短い
    子プロセス（つくしのような常駐プログラムは2行しか出しません）を
    続けて実行すると、開始位置が毎回2行ずつ下がっていました。ホームへ
    戻してから渡すことで、毎回同じ位置から始まります
  - **戻ってきた後に反転した1セルが残る問題を修正**：正体は PC-98 の
    **ハードウェアテキストカーソル**で、VRAM へ何を書いても消せません
    （このプログラムの再描画も `vram_clear_all()` も届かない）。子プロセスへ
    渡す直前に表示し、戻ってきた直後に必ず隠し直すようにしました

## 実装メモ

- ディレクトリ読み取りは DOS INT 21h の AH=1Ah（DTA設定）/ 4Eh（FindFirst）/
  4Fh（FindNext）、カレントディレクトリ取得は AH=47h、ディスク空き容量取得は
  AH=36h を使用しています。いずれも公開されている DOS の標準ファンクションです。
- 画面本体の出力は第5マイルストーンからテキストVRAM（`0xA0000`/`0xA2000`）
  への直接書き込みです。ANSI 風のエスケープシーケンスは、SJIS/半角罫線と
  無関係な用途（点滅カーソルの表示/非表示・位置合わせ、関数キー行の解放/
  復帰）にのみ残っています。SmallerC は small model のためセグメントを
  跨ぐVRAM書き込みは inline asm（`vram_put_raw()`）で行っています。
- SmallerC の 16-bit モードには `long` 型が無いため、ファイルサイズやディスク
  容量などの32ビット値は、上位16ビットと下位16ビットを組にした自前の演算
  （加減算・乗算・10での除算）で扱っています。
- 矢印キーは、IBM PC 系でよくある「`0x00` + 拡張スキャンコード」の2バイト
  方式ではなく、PC-98 の DOS（旧: INT 21h AH=08h）では単独のコントロール
  コードとして返ってきます（実測: ↑=0x0B、↓=0x0A、←=0x08、→=0x0C）。
  第10マイルストーンでキー入力を BIOS（INT 18h AH=00h）へ移行した後も、
  `dos_getch()` の戻り値としてはこれと同じ値を返すようにしてあるため、
  この節で書いた値そのものは変わっていません（詳細は前節「タイトルの
  中央寄せ、キー入力のBIOS(INT 18h)化」参照）。
  `^E`/`^X` を上下移動の代替キーとして割り当てていますが、`^S`
  （WordStar 系の慣行では左移動）は割り当てていません。DOS のコンソール
  ドライバが `^S` を XOFF として横取りし、`^Q` を押すまで画面出力が
  止まってしまうことを実機で確認したためで、この制約自体は INT 18h への
  移行で理屈の上では解消していますが、`^S` を BIOS 経由で改めて実測
  してから割り当てるかどうかは今回のスコープ外としています。

## 文字コードについての注意（重要）

**`SUMIRE.C` は CP932（Shift_JIS）でエンコードされており、`g_msgJA[]` の
日本語メッセージは生の CP932 バイト列です。このファイルの文字コードを
UTF-8 などへ変換しないでください。**

過去に一度、このファイル全体を UTF-8 として読み書きするツールにかけた際、
CP932 として妥当だがUTF-8としては不正なバイト列が `U+FFFD`（置換文字）へ
黙って変換され、日本語メッセージが全滅した事例があります。しかもビルドは
通り、英語モード（`/E`）では何の異常も見えなかったため、実機で日本語モード
（既定）を使って初めてクラッシュとして発覚しました（`U+FFFD` は SJIS 解釈で
3セル幅を持つため、ヘッダ枠の想定幅を超えてバッファが溢れる）。

このファイルを編集するときは:
- ファイル全体を読み込んで書き戻すような変換的な編集をしない
- どうしても必要な場合はバイト列のまま（Python なら `open(path, 'rb')` /
  `open(path, 'wb')`）扱い、`errors='replace'` は使わない
- 編集の前後で `check.py`（後述）を実行し、CP932 として妥当であること・
  `U+FFFD`（バイト列としては `EF BF BD`）が含まれていないことを確認する
- `grep` はこのファイルに対して使わない（0x85 等のバイトが行終端として
  誤解釈され、存在する行を黙って読み飛ばすことがある）。検索や件数確認は
  Python 等でバイト単位に行う

## 検査スクリプト（check.py）

`check.py` は `SUMIRE.C` に対して以下を検査します。1つでも失敗すると
非ゼロで終了します。

1. `SUMIRE.C` が CP932 として正しくデコードできる
2. バイト列 `EF BF BD`（`U+FFFD` の UTF-8 表現）が含まれていない
3. `g_msgJA` と `g_msgEN` の要素数が一致する
4. どちらのメッセージテーブルにも空文字列が無い
5. タイトル `g_title`（第11マイルストーンから `g_msgJA`/`g_msgEN` の外に
   ある固定の英語文字列）が、ヘッダ枠のタイトル用実効幅（日時表示分を
   差し引いた幅）に収まっているか
6. 各メッセージが、実際の使われ方（ヘッダ枠／ダイアログ／実行時に結合される
   フラグメント）に応じたセル幅上限に収まっているか（日英とも）
7. 画面最下行のファンクションキー表示（`g_fkeyLabel[]`/`g_fkeyCol[]`/
   `g_fkeyHiPos[]`。第6マイルストーンから `g_msgJA`/`g_msgEN` の外に
   ある言語非依存の構造）について、10個のフィールド全てが実測した
   開始桁・`FKEY_FIELD_WIDTH`（6セル）幅に収まり、フィールド同士が
   重ならず、画面幅（80桁）をはみ出さないこと。ラベルを長くする
   故障注入テストで実際に検出できることを確認済み（後述）

実行方法:

```
cd guest/sumire
python3 check.py
```

（省略時は同じディレクトリの `SUMIRE.C` を検査します。別のパスを検査したい
場合は `python3 check.py <パス>` のように引数で指定できます。)

## 実機で確認すべきこと（第10マイルストーン、未検証）

キー入力を BIOS(INT 18h) へ移行したこと自体は WebNP2/FreeDOS(98) 上での
実測に基づくが、**実機での動作確認はまだ行っていない**。次回実機確認時に、
少なくとも以下を確かめること:

1. **ESC単独で中止できること** — 何もファンクションキーを押さずに `ESC`
   キーだけを押し、一覧画面が正しく終了する（誤ってファンクションキー
   として扱われて何も起きない、ということがない）
2. **ファンクションキーが正しく効くこと** — `F3`（Copy）・`F4`（Delete）・
   `F5`（Rename）・`F6`（Move）・`F7`（mKdir）・`F10`（Quit）をそれぞれ
   押し、対応するコマンドが実行される（プログラムが終了してしまう、
   何も起きない、といったことがない）ことを1つずつ確認する
3. 未実装の `F8`/`F9` を押しても何も起きない（クラッシュしない）
   ことも確認する（`F1` は第12マイルストーンで Logdsk を割り当てた）
4. **矢印キー・HOME・←/BS の区別** — ↑↓←→、HOME、および一覧画面での
   `←` と入力ダイアログでの `BS` が、それぞれ従来どおりの動きになる
   ことを確認する（INT 18h ではスキャンコードが別々になるため、
   `dos_getch()` 内の変換が正しいかを実機で裏取りする）
5. **`^S`/HELP は今回未対応のまま** — 割り当てていないので何も起きない
   はずだが、意図せず別の動作を引き起こさないことを確認する。**内蔵
   ビューアの `ROLL UP`/`ROLL DOWN`（第11マイルストーンで実装）** は
   実機で実際に22行送り/戻しになること、`ROLL DOWN` が先頭で止まる
   ことを確認する。**一覧画面（ファイラ本体）では `ROLL UP`/`ROLL DOWN`
   を押しても何も起きない**（今回割り当てていない）ことも確認する
6. **F2/eXec から戻った後も入力が正常なこと** — 子プロセス（外部
   プログラム）が BIOS のキーバッファやキーボード関連の状態に触って
   いる可能性がある。`F2`/`X` で何かプログラムを実行して戻った直後に、
   矢印キー・ファンクションキー・ESC がすべて元どおり効くことを
   確認する（キーが効かなくなる、二重に入力される、といった異常が
   ないか）
